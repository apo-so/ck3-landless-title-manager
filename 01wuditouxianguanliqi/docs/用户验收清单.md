# v0.2.0 用户验收清单（历史版本）

本页保留 0.2.0 的验收步骤。0.4.3 的人物入口见[人物互动与窗口](互动窗口.md)。

状态：源码实现、静态检查；引擎解析、布局、实际加载和以下场景均 NOT RUN。请用独立测试存档，保留操作前 PRE 副本。原军政分离无需启用；先测试本体+独立 Mod，再分别联用。

1. 打开领地决议“无地头衔管理器”，或右键自己使用同名入口。顶栏“新建头衔”无需选中一行。“查找/补建独立宅邸”有本 Mod 既有宅邸时打开其编辑，否则进入显式创建流程。
2. 普通路径先选公爵、普通继承、输入独特中文名、不复制模板，确认前检查金币/国库费用和威望奖励。确认后核对实际名称、title ID、duchy、holder 和无地类型。结果码2只代表脚本即时检查，存读档和未来行为另验。
3. 分别检查公爵、国王、皇帝、霸权和伯爵。伯爵暂无旧费率，原型免费。费用规则关闭时不结算；创建一次只结算一次。失败/不完整对象不自动重试或清理。
4. 模板只是建议来源：选择行后点创建，可明确复制纹章/颜色和首府/法理。模板可以不持有；模板持有人也可作为创建 holder。核对复制源没有被修改。首府来自伯爵领，住所位置是省份，两者不是同一字段。
5. 从头衔详情点“后期属性编辑”。分别测试改名、恢复默认、随机/复制纹章、颜色、首府和法理。只改名称时其他字段必须保持；取消不得修改对象。颜色和纹章可以来自不同标记头衔；搬住所不得取消已排队的首府修改。
6. 规则菜单轮换保持→是→否→保持。缺可靠 getter 的字段回执2只代表请求，不代表实际生效。真实触发分割继承、自动宣称、无合适继承人和获得同级头衔后再判断相应行为。
7. 法律逐项添加/移除9个明确法律；添加可替换同组旧法律，移除会让该组为空。使用原生无费用/效果版 add_title_law / remove_title_law，不调用 *_effects。分别检查目标法律和其他组未被清空。
8. 转让作为独立事务，只对普通非住所头衔开放。先标记接收者持有的头衔，再确认；核对原 title ID 保留，实际 holder 改变，政治关系与其他头衔仍合理。转让不提交编辑草稿。
9. 独立宅邸路径检查新 title 实际 tier、holder、title_domicile、domicile type=sltm_residence、owner、location 和 sltm_residence_main_01。从详情或结果页打开实际住所，不能仅看“创建成功”。无模板时位置由构造器确定，可随后用已标记头衔首府省份搬迁。
10. 另测当前政体后端：行政/冒险者/游牧/中华或日本及教会政体各自独立验收；此后端是源码原型，并未证明原生政府适用于通用构造器。核对 estate/camp/yurt/east_asian_estate/japanese_manor/ecclesiastical_domicile 的实际类型，不把默认 county 等同住所类型。
11. 建立至少两座住所；顶栏 ensure 不应再次创建，显式“新建”可继续新增。分别选择每个 title 并打开、搬迁其实际住所。核对旧 title/住所绑定、建筑、资源、holder 政体、主头衔和原生默认住所。即时脚本仅检查旧持有人/住所绑定，建筑和资源保留要人工核验。
12. 原生世族、冒险者、游牧及其他/未知来源住所载体：旧销毁、剥夺、授予与新生命周期编辑不可执行。详情和旧互动两条入口都测。普通非住所头衔的两段销毁仍可用。本版不提供额外住所拆除。
13. 每一已测路径观察 D1，再保存重读，最后完全退出并冷启动重读。已有37组设计矩阵保持独立结果，不用一项通过覆盖其他组。

请记录 PRE→NOW→D1→SAVE_RELOAD→COLD_RELOAD，每步实际对象和费用差异。起点已等于目标且无法区分执行结果时记 INCONCLUSIVE，不当作 PASS。游戏错误日志、窗口截图和实际对象结果分别保留。
